# Remote task pack, 15 Nov 2026 (repo LarytheLord/same-facts-softer-words, private)

Context for every task: this repo is a research sprint on how LLM judges score a company's own
statement against the regulator's record of the same incident. README.md explains the layout.
`./reproduce.sh` recomputes every headline number from saved raw outputs with no API calls.
There are NO API keys in this environment: never run anything with `--live`.

## Shared rules
RULES: Work only on a new branch named in the task. Open the result as a DRAFT pull request and stop. Never push to main, never merge, never change repository settings. Never run any script with --live or anything that needs an API key; if a step needs one, skip it and say so in the PR body. Do not modify any file under harness/results_*/ or data/*.jsonl (saved raw outputs are the evidence). Plain ASCII only, no em dashes. Write commit messages and the PR body in plain first-person English with no mention of any AI tool, no Co-Authored-By line and no generated-by footer. In the PR body list exactly which commands you ran and their results, and anything you could not verify. Keep the change to the one purpose of the task.

## C1 (tests for the new analysis scripts)
Branch test/analysis-scripts. Add pytest tests (offline, using small fixture files you create under harness/tests_fixtures/) for: harness/two_step.py (gate logic: majority of repeats must say harmed and extent STATED; INSUFFICIENT otherwise; close if score <= threshold), harness/clearance.py (threshold counting), harness/omission_arm.py (tokens and is_subsequence: deletions pass, rewording or reordering fails; refuses to run without --live and refuses to overwrite an existing output), harness/judge_check.py (refuses mock output into a folder without "mock" in its name; refuses a folder that already has raw_*.jsonl), harness/rescore_probes.py (rebuilds the committed summary rows exactly: compare its output for harness/results_scale and harness/results_omission with the rows in their summary.md). Run `python3 -m pytest harness -q` and `./reproduce.sh` and paste the last lines of both in the PR body. Do not change script behaviour; if a test reveals a bug, describe it in the PR body and fix it in a separate commit.

## C3 (next-step research design, no code)
Branch docs/next-steps. Write docs/NEXT_STEPS.md, about 1,200 words, plain and specific, for the experiments reviewers asked for:
(a) validating the two-step gate against human labels of "is the harm and its extent stated?" (sample size, blinding, agreement statistic, cost);
(b) a held-out set of 20-30 new company-vs-regulator incident pairs (sources: OSHA, CSB, CPSC, FTC, SEC, FDA, EPA, UK HSE; selection rule fixed in advance; how to avoid the regulator-is-harsher-by-construction objection);
(c) applying the gate-before-score protocol to a multi-turn animal-welfare benchmark scored by an LLM judge, in the style of MANTA (arXiv 2605.16301): what a vague or non-committal answer looks like, what the gate question becomes, metric, cost;
(d) an AI-control version: an agent's own narration of its actions versus its tool trace, monitored by an LLM, with softened and incomplete narration; metric = monitor recall at 1% false positives; reusable public setups.
For each: hypothesis, design, metric, rough cost in API calls on free or cheap open models, and the main threat to validity. Cite only papers already listed in report/CITATIONS_VERIFIED.json; anything else must be marked UNVERIFIED.
